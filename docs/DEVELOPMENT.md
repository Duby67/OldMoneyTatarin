## Получение исходников

Папка проекта теперь содержит собственную документацию. Не клонируйте upstream поверх неё с заменой файлов. На этапе подготовки используйте соседний временный checkout, затем согласуйте объединение деревьев: исходный README сохраните в истории или отдельном документе с указанием происхождения. Существующие документы переносите без потери содержания; конфликты разрешайте явно.

Порядок подготовки:

1. Проверить Git, доступ к исходному репозиторию и его официальные инструкции.
2. Получить [исходники](https://github.com/ElyPrismLauncher/Launcher) вместе с субмодулями через `git clone --recurse-submodules` в свободную папку.
3. Зафиксировать URL, ветку, commit и состояние субмодулей. Проверить `.gitmodules` перед дополнительной загрузкой.
4. Перенести checkout в рабочую папку с сохранением истории Git и местной документации. Не включать подготовительные документы в эталонную сборку upstream.
5. Сохранить исходный репозиторий как remote `upstream`; `origin` настроить только после получения адреса собственного репозитория.
6. Проверить реальные ветки и создать отдельную ветку разработки. Планируемые имена и правила описаны в [AGENTS.md](../AGENTS.md).

Git-операции в этом списке — план следующего этапа, а не выполненные действия.

## Инструменты и зависимости

| Компонент | Что проверить | Возможный способ подготовки |
| --- | --- | --- |
| Git | Доступность и работу субмодулей | Существующая установка или Git for Windows |
| CMake | Версию относительно требований upstream | Существующая установка или локальный набор инструментов |
| C++ компилятор | Поддерживаемый upstream компилятор и архитектуру x64 | Visual Studio Build Tools с компонентами C++, если требуется MSVC |
| Windows SDK | Совместимость с выбранным компилятором | Компонент выбранного набора сборки |
| Qt6 | Требуемую версию и модули, соответствие ABI компилятора | Отдельный Qt Kit под выбранный компилятор |
| Генератор сборки | Поддержку выбранного генератора | Ninja либо генератор Visual Studio по инструкции upstream |
| Прочие библиотеки | CMake, субмодули и конфигурацию CI | Механизм, используемый upstream, без произвольной замены |
| Java | Нужна ли для сборки, вспомогательных задач или только запуска игры | Версия по требованиям upstream и выбранного Minecraft |

Это кандидаты для проверки, а не подтверждённый полный список. Не устанавливайте всё заранее. Сначала изучите официальные инструкции из выбранного checkout и конфигурацию Windows CI. Не меняйте системный `PATH`, реестр и политики ради пробной сборки; используйте отдельную сессию и локальные пути, где это возможно.

## Проверка исходной сборки

Сначала соберите неизменённый commit upstream в отдельном каталоге сборки. Точные команды CMake добавляются в этот документ после проверки инструкций проекта: генератор, Qt Kit, параметры и имена целей пока неизвестны.

1. Записать версии Windows, Git, CMake, компилятора, SDK, Qt и генератора.
2. Проверить чистоту исходников и состояние субмодулей.
3. Выполнить конфигурацию CMake по официальной инструкции; сохранить команду и журнал.
4. Собрать требуемую конфигурацию и сохранить первый существенный сбой, если он возникнет.
5. Запустить доступные проверки upstream, если окружение позволяет.
6. Попробовать открыть приложение и проверить появление главного окна. Сам по себе этот запуск не подтверждает авторизацию, загрузку игры или все целевые возможности.

Для ошибки укажите стадию, команду, сообщение, установленную причину либо гипотезу и следующий проверяемый шаг. Не заменяйте отсутствующую зависимость изменением функциональности лаунчера.
