# Разработка

## Окружение

Проверенная конфигурация Windows x64: Visual Studio Build Tools 2026 с MSVC и Windows SDK, CMake 4.3.1, Ninja 1.12.1, Qt 6.10.2 (MSVC 2022 64-bit), JDK 17. Для Qt нужны NetworkAuth, Image Formats и LinguistTools с `lrelease`; SVG входит в комплект. Системную Java менять не требуется.

По умолчанию `scripts/build.ps1` использует:

| Инструмент | Путь |
| --- | --- |
| Qt | `.cache/deps/Qt/6.10.2/msvc2022_64/` |
| vcpkg | `.cache/deps/vcpkg/` |
| JDK 17 | Единственный каталог в `.cache/deps/java/`, иначе `JAVA_HOME` |
| MSVC и Ninja | Установка Visual Studio Build Tools, найденная через vswhere |

Зависимости C++ описаны в `vcpkg.json`, версии фиксирует `vcpkg-configuration.json`. Подготовка локальной копии vcpkg при первом запуске:

```powershell
git clone --depth 1 https://github.com/microsoft/vcpkg.git .cache/deps/vcpkg
$baseline = (Get-Content -Raw vcpkg-configuration.json | ConvertFrom-Json).'default-registry'.baseline
git -C .cache/deps/vcpkg fetch --depth 1 origin $baseline
git -C .cache/deps/vcpkg checkout --detach $baseline
& .\.cache\deps\vcpkg\bootstrap-vcpkg.bat -disableMetrics
```

При смене baseline повторно запустите bootstrap: исполняемый файл vcpkg должен соответствовать его конфигурации инструментов.

Перед сборкой получите субмодуль:

```powershell
git submodule update --init --recursive
```

## Сборка

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Jobs 6 -Install
```

Скрипт подключает MSVC x64, Qt и JDK только для своего процесса. `ExecutionPolicy Bypass` также действует только в этом процессе. Первый запуск CMake скачивает и собирает зависимости vcpkg; требуется интернет. LTO в скрипте отключён.

| Параметр | Назначение |
| --- | --- |
| `-Configuration` | `Release` по умолчанию, также `Debug` и `RelWithDebInfo` |
| `-Jobs` | Число параллельных задач, по умолчанию 2 |
| `-Install` | Скопировать приложение и зависимости в локальную установку |
| `-Installer` | Собрать Release-установщик через локальный Inno Setup; [подробности](RELEASING.md#локальный-установщик-windows) |
| `-ConfigureOnly` | Выполнить только конфигурацию CMake |
| `-BuildDirectory` | Другой каталог сборки; новый пустой каталог позволяет проверить сборку с нуля |
| `-QtRoot`, `-VcpkgRoot`, `-JavaHome` | Пути к собственным установкам инструментов |

Например, для проверки с нуля добавьте `-BuildDirectory dist/verify/new-build`, если такого каталога ещё нет.

Результаты по умолчанию:

- `dist/build/windows_msvc/` — сборка;
- `dist/app/windows_msvc/` — приложение с библиотеками после `-Install`;
- `dist/vcpkg_installed/` — зависимости C++.

`dist/` и `.cache/` исключены из Git. CMake поддерживает только 64-битную Windows; единственный пресет — `windows_msvc`. Тесты основного проекта удалены, тесты внешнего NBT-субмодуля отключены. Общие исходники могут сохранять неиспользуемые платформенные фрагменты upstream.

## Перевод и проверка очистки

`launcher/translations/bundled/ru.ts` компилируется через `Qt6::lrelease` и включается в ресурсы приложения как `:/translations/ru.qm`. Русский язык выбран по умолчанию для новых настроек. Английский интерфейс и загрузка локальных PO/QM сохранены; сетевой индекс и автоматическая загрузка переводов удалены. Источник и лицензия пакета указаны рядом с ним.

После очистки проверены XML файлов UI/QRC, наличие ресурсов и файлов в списках CMake, ссылки на удалённые классы и поля UI. 15 ноября 2026 года команда `scripts/build.ps1 -Jobs 6 -Install` успешно выполнила конфигурацию CMake, компиляцию Release, линковку и установку в `dist/app/windows_msvc` (код завершения 0). Использовался существующий каталог сборки; отдельная сборка с нуля не выполнялась.

При проверке исправлены несовместимые сигнатуры `target_link_libraries` после подключения ресурсов Qt, применение флагов компилятора к служебным целям, оставшееся подключение сигнала профилировщика, ссылка на удалённую платформу переводов и неиспользуемая переменная мастера языка. Удалены устаревшие назначения Tab. Строгие флаги `/W4 /WX` сохранены.

Предупреждения CMake о политиках установки CMP0177/CMP0207, ненайденных необязательных Vulkan headers и `clang-format` не препятствуют сборке. Русский пакет скомпилирован через `lrelease` и включён в исполняемый файл; лицензия перевода установлена в `licenses/translations/LICENSE`.

Следующая ручная проверка: первый запуск без сети (русский интерфейс и правовые уведомления), настройки, локальные логи и скриншоты, затем Ely.by и запуск Minecraft. Работоспособность этих сценариев после изменений ещё не подтверждена.

## Upstream и ветки

База — [PineconeMC 11.1.2](https://github.com/ElyPrismLauncher/Launcher/releases/tag/11.1.2), commit `ac99ad44ef98dd73dd9626c7b7b2b668dd8cbd5c`. Remote `upstream` указывает на исходный проект, `origin` — на OldMoneyTatarin.

| Ветка | Назначение |
| --- | --- |
| `vendor/pineconemc` | Чистый стабильный upstream с полной историей |
| `develop` | Рабочая ветка нашего проекта |
| `main` | Выпуски |

Обновление выполняется вручную:

1. На чистом рабочем дереве выполнить `git fetch upstream --tags`, выбрать стабильный тег и изучить изменения, особенно исправления безопасности.
2. В `vendor/pineconemc` выполнить `git merge --ff-only <проверенный-тег>`. При расхождении истории остановиться и выяснить причину.
3. Подготовить обычное слияние `vendor/pineconemc` в `develop`, сохранив родительскую связь. Не использовать squash и не восстанавливать удалённую инфраструктуру автоматически.
4. Обновить субмодуль, проверить локальную сборку и затронутые сценарии, затем обновить запись о базе в этом документе.

Tracking `upstream/release-11.x` не гарантирует стабильность каждого commit: обычный `git pull` может захватить невыпущенные изменения. При смене релизной линии tracking нужно пересмотреть. Отдельные исправления можно переносить с сохранением ссылки на исходный commit.

Собственная версия и патчноуты ведутся по [инструкции выпуска](RELEASING.md). Лицензионные уведомления upstream и зависимостей сохраняются при очистке и обновлении.
