# Этапы разработки

## 0. Документационная основа — выполнено

Созданы правила работы, описание проекта, предварительная карта исследования и порядок подготовки окружения. Это не завершение технической подготовки.

## 1. Подготовка репозитория и окружения — в работе

- Получены upstream, его история и субмодуль; существующие документы сохранены.
- Настроен remote `upstream`, сохранены `origin` и рабочая ветка `develop`.
- Создана чистая ветка `vendor/pineconemc` на стабильном PineconeMC 11.1.2; переход `develop` на эту базу завершён слиянием с сохранением связи историй.
- Введены собственная версия и патчноуты; описан выпуск из `main` с локальной сборкой. GitHub хранит только код и документацию; сборка приложения ещё не проверена.
- Исследовать компоненты и официальные инструкции сборки.
- Проверить зависимости и лицензии.
- Попробовать собрать и запустить исходный лаунчер без функциональных изменений.
- Обновить документацию проверенными фактами и подготовить технический отчёт.

Критерий завершения: воспроизводимая исходная сборка либо конкретный перечень блокирующих причин и действий для их устранения. После этого остановиться до отдельного задания.

## 2. Определение MVP и проектирование управляемого профиля — по отдельному заданию

Определить состав MVP — первой рабочей версии продукта, источник модпака, поддержку версий, модель манифеста, доверие к обновлениям и границы управляемых файлов. Определить сценарии первого запуска, обновления, восстановления, работы без сети и сохранения данных пользователя. Результат — согласованная спецификация и точки интеграции в проверенном коде.

## 3. Реализация синхронизации модпака — по отдельному заданию

Создать отдельный профиль и синхронизацию по утверждённой спецификации. Проверить установку, обновление, повреждённые загрузки, прерывание операций и сохранность пользовательских данных.

## 4. Java, память и совместимость — по отдельному заданию

На основе существующих механизмов проверить и при необходимости доработать подбор Java, её установку и настройки памяти. Провести проверки Vanilla, Forge, NeoForge, Fabric, Ely.by, скинов и каталогов готовых сборок.

## 5. Оформление, установщик и обновления — по отдельному заданию

Подготовить собственное оформление, упаковку для Windows x64, установщик и механизм обновления. Проверить лицензии, подпись, обновление существующей установки, восстановление после ошибки и сохранность профилей.

## 6. Подготовка выпуска — по отдельному заданию

Проверить чистую установку на Windows 10/11 x64, основные пользовательские сценарии и состав распространяемых файлов. Подготовить инструкции, сведения о лицензиях и процедуру синхронизации с upstream.
