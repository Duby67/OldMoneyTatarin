# Предварительная архитектура

## Статус исследования

Документ описывает области исследования по требованиям проекта. Исходники получены; commit указан в [подготовке окружения](DEVELOPMENT.md). Имена классов, связи компонентов и доступные возможности upstream ещё не исследованы. Предлагаемые границы синхронизации модпака не являются утверждённым проектом реализации. Целевая платформа форка — Windows 10/11 x64.

## Карта компонентов для проверки

| Область | Что найти в исходниках | Что зафиксировать |
| --- | --- | --- |
| Ely.by | Учётные записи, авторизация, обновление сессии, передача данных игре | Поток входа, хранение секретов, обработку истечения сессии |
| Скины | Получение профиля и применение скинов Ely.by | Сетевые сервисы, кэш и связь с запуском игры |
| Установка игры | Метаданные версий, загрузку файлов и библиотеки | Проверки целостности, обработку ошибок и повторные попытки |
| Загрузчики | Установку Forge, NeoForge и Fabric | Поддерживаемые версии и ограничения совместимости |
| Готовые сборки | Каталоги, импорт и установку модпаков | Доступные источники, форматы и требования API |
| Профили | Создание и хранение экземпляров игры, настройки и блокировки | Разделение пользовательских и управляемых данных |
| Java и память | Обнаружение и установку Java, выбор версии, аргументы JVM | Правила совместимости и ограничения памяти |
| Запуск игры | Подготовку запуска, процесс, журналы и завершение | Точку проверки готовности профиля до запуска |
| Обновление лаунчера | Проверку версий, загрузку обновлений и упаковку | Существующие механизмы, подпись и каналы обновлений |

После исследования для каждой области следует указать проверенный путь и символ, commit upstream и краткое описание потока выполнения.

## Возможные точки интеграции синхронизации модпака

Предварительно рассматриваются создание отдельного управляемого экземпляра игры, проверка его состояния перед запуском и использование существующего механизма загрузки файлов. Окончательный выбор зависит от архитектуры upstream.

Будущий проект синхронизации должен определить:

- источник, версию и проверку подлинности манифеста модпака;
- перечень управляемых файлов и правила сохранения миров, настроек и пользовательских файлов;
- безопасное применение обновления, восстановление после ошибки и работу без сети;
- блокировку синхронизации при запущенной игре и поведение при параллельных операциях;
- совместимость версий Minecraft, загрузчика и Java;
- условия распространения каждого мода и скачивания из каталогов.

На текущем этапе эти механизмы не реализуются.

## Лицензии и распространение

До распространения форка необходимо проверить лицензионные файлы на выбранном commit, уведомления об авторах, лицензии субмодулей, библиотек, ресурсов и включаемой Java. Отдельно изучаются требования к публикации исходников и изменений, использованию названий и графики, доступу к каталогам сборок и распространению модов. Происхождение от Prism Launcher само по себе не подтверждает условия для всего выбранного дерева исходников.
