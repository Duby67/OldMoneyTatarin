# Сборки TATARIN

Исходная игровая папка используется только для чтения. Снимки и раздача хранятся в
`run/`, исключённом из Git. Не добавляйте туда ссылки на исходные пользовательские папки.

## Снимок

Из корня репозитория, с Python 3.12 или новее:

```powershell
python scripts/tatarin/snapshot.py <исходная-папка> run/tatarin/snapshot-v1 --minecraft 1.21.1 --neoforge 21.1.264
```

Скрипт требует новый каталог назначения. Разрешённые корневые папки и политика
файлов перечислены в `scripts/tatarin/snapshot.py`. Миры, карты, история, кеши,
пользовательские файлы в корне и резервные копии не входят в снимок.
Конфиги с обнаруженными непустыми полями учётных данных исключаются без вывода значений.
Это дополнительный фильтр, а не гарантия обезличивания произвольных файлов:
перед публичной раздачей требуется ручная проверка состава и содержимого.

`snapshot.json` содержит только версии компонентов, относительные пути, размеры,
SHA-256 и политику файлов. `managed` означает управление сборкой, `seed` —
начальное содержимое с сохранением последующих пользовательских изменений.
Файлы вне разрешённых папок необходимо разбирать отдельно, не копировать автоматически.

## Локальный источник

```powershell
python scripts/tatarin/publish.py run/tatarin/snapshot-v1 run/tatarin/server --release local-1
python scripts/tatarin/serve.py run/tatarin/server
```

Источник доступен по `http://127.0.0.1:18765/`, завершение — Ctrl+C.
Сервер слушает только этот компьютер. Это инструмент разработки, не публичный хостинг.
Публикация копирует файлы в `objects/<sha256>`, затем создаёт неизменяемый манифест
и в последнюю очередь атомарно заменяет `v1/catalog.json`. ID выпуска повторно
использовать нельзя. Для следующего выпуска создайте новый снимок и новый ID.
Каталог содержит список сборок и SHA-256 их манифестов; манифест задаёт полный
состав выпуска, версии Minecraft/NeoForge и патчноут. Секреты и исходные абсолютные
пути в эти документы не записываются.

## Установка в лаунчере

В окне добавления сборки откройте `TATARIN`, нажмите «Обновить каталог» и выберите
RegionalWorlds. Новый адрес по умолчанию — `https://play.fleexpoint.space:8443/`;
он сохраняется в настройке `TatarinDevSource` (старое имя ключа оставлено для
совместимости). Разрешён HTTPS с обычной проверкой сертификата Windows;
HTTP допустим только на `127.0.0.1` для тестов. Редиректы отклоняются.
Отдельной цифровой подписи манифеста пока нет: доверие к источнику обеспечивает
HTTPS, а целостность объектов проверяется SHA-256 из каталога и манифеста.

Прежний адрес `http://127.0.0.1:18765/` заменяется новым в окне каталога.
У существующей RegionalWorlds с этим точным адресом переход выполняется при
синхронизации; новый адрес сохраняется после успешного обновления. Пользовательские
адреса других источников автоматически не меняются. Эти изменения исходников
ещё не входят в опубликованный установщик 0.3.0.

## Отдельная серверная раздача

Конфигурация находится в `server/tatarin/compose.yaml` и `server/tatarin/Caddyfile`.
Это отдельный Compose-проект на порту 8443, без изменения существующего Caddy,
его контейнера, сетей и конфигурации на 80/443. Монтируются только каталог
`public` с файлами раздачи, отдельные `certificates/fullchain.pem` и
`certificates/privkey.pem`, а также собственный Caddyfile. Доступ к данным —
только для чтения; листинг каталогов выключен. Отдаются только `/v1/*` и
`/objects/*`. Закрытые ключи и файлы раздачи не хранятся в Git.

Для запуска необходимы DNS A-запись поддомена на IP сервера, доступный снаружи
порт 8443 и отдельный доверенный сертификат. Конфигурация рассчитана на Linux-пользователя
с UID/GID 1000; при переносе проверьте права на сертификаты и файлы.
Из каталога конфигурации используется `docker compose -p tatarin-source up -d`.
Обновление файлов раздачи выполняется через новый каталог выпуска: сначала
проверяются все объекты и манифесты, затем меняется раздаваемый каталог; старый
выпуск сохраняется для отката. Сертификат нужно продлевать отдельно и перезагружать
только контейнер этого Compose-проекта.

Сертификат для независимой раздачи можно выпустить Certbot через DNS-01,
добавив TXT `_acme-challenge.play.fleexpoint.space`. Этот способ не требует
доступа к портам существующего Caddy. При ручном добавлении TXT автоматического
продления нет: перед истечением сертификата нужно повторить DNS-проверку,
обновить отдельные файлы сертификата и перезапустить только `tatarin-source`.
См. [документацию Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#manual).

Серверный снимок `server-1` загружен; проверены SHA-256 всех 3604 файлов.
Раздача работает на `https://play.fleexpoint.space:8443/`. Внешняя проверка
с компьютера подтвердила доверенный TLS, каталог, SHA-256 манифеста и трёх
представительных объектов (крупнейший файл, обязательный конфиг и `seed`).
Проверены запрет служебных путей и листинга. Сертификат Let's Encrypt действует
до 13 февраля 2027 года; автоматическое продление не настроено.
Существующие сервисы на 80/443 не изменялись и не перезапускались.
Новые изменения C++ не компилировались по просьбе пользователя; проверка
этого HTTPS-источника непосредственно в новой сборке лаунчера ещё не выполнена.

Создаётся отдельный экземпляр типа `tatarin`. Minecraft и NeoForge устанавливаются
существующим механизмом лаунчера. Для загрузки их метаданных, библиотек и ресурсов
требуется интернет; локальная раздача содержит только содержимое модпака.
Установленный манифест хранится в `tatarin/installed.json` экземпляра.

Общий каталог экземпляров задаётся настройкой `InstanceDir`, по умолчанию —
`instances` внутри каталога данных лаунчера. Он не совпадает с папкой установки
программы. При быстрой настройке можно выбрать другой каталог, например
`D:\TATARIN\Instances`. Общий каталог выбирается один раз; у каждой сборки внутри
него своя папка. Полный текущий путь показан в разделе TATARIN; кнопка «Настроить папку
сборок…» открывает настройки лаунчера, где в разделе «Папки» можно изменить
каталог экземпляров. Внутри него каждая сборка получает отдельную папку,
игровые файлы находятся в её подкаталоге `minecraft`.
Смена общего каталога не переносит ранее установленные сборки автоматически.
Java, общие библиотеки Minecraft и ресурсы игры используют свои существующие
пути; выбор `InstanceDir` не переносит весь профиль лаунчера.

Изолированный проверочный исполняемый файл собирается из `tests/tatarin/CMakeLists.txt`
с Qt6 Core/Network. Он принимает URL источника и новый каталог назначения,
проверяет установку через HTTP и SHA-256 всех установленных файлов.

## Проверка перед запуском

У экземпляров `tatarin` перед загрузкой метаданных Minecraft и подбором Java
выполняется синхронизация. Обычные экземпляры эту задачу не запускают.
Проверяются SHA-256 управляемых файлов, новые объекты сначала загружаются в
`tatarin/downloads/`. Неизменённые файлы повторно не скачиваются.

Перед заменой или удалением создаются копии в `tatarin/backups/<transaction>/`.
Журнал `tatarin/pending.json` сохраняется до первого изменения рабочих файлов.
При ошибке выполняется восстановление; после аварийного завершения оно повторяется
при следующей проверке. До успешного восстановления запуск останавливается.
На время применения отмена недоступна; параллельную синхронизацию блокирует lock-файл.
Резервные копии и кеш пока сохраняются без автоматической очистки.

Если источник недоступен, лаунчер предлагает запуск локального выпуска только
после проверки всех обязательных файлов. По умолчанию выбран отказ. Ошибка
формата, опасные пути или несовпадение хешей не обходятся этим предложением.

Интеграционные проверки: `python tests/tatarin/integration.py <путь-к-tatarin-check.exe>`.
Для запуска нужны Qt DLL в `PATH`; проверки используют временные папки и собственный
loopback-сервер, не затрагивают исходную сборку и пользовательские экземпляры.

## Владение файлами

Политика задаётся для каждого файла манифеста:

| Политика | Поведение |
| --- | --- |
| `managed` | Восстановление содержимого по SHA-256; замена и удаление с резервной копией |
| `seed` | Добавление нового стартового файла, если его ещё нет; сохранение пользовательских изменений и удаления |

Реестр `initializedSeeds` в локальном манифесте сохраняет факт выдачи стартовых
файлов даже после их исчезновения из следующих выпусков. Удалять пользовательский
файл или возвращать ранее удалённый `seed` синхронизация не будет.
Устаревшие файлы удаляются только по предыдущему манифесту и только с политикой `managed`.
Папки целиком не очищаются. Локальные изменения обязательных конфигов уступают
манифесту, их исходное содержимое остаётся в резервных копиях экземпляра.

Дополнительные моды, включая `.disabled`, сохраняются. Предупреждение об их наличии
выводится в журнал запуска, список виден на странице `TATARIN` настроек экземпляра.
Там же показаны установленный выпуск, версии компонентов, патчноут и правила файлов.
Ссылки и Windows junction в управляемых путях не поддерживаются.

## Память сборки

Необязательный объект `memory` в манифесте задаёт `minMiB`, `maxMiB` и
`systemReserveMiB` (по умолчанию 2048 МиБ). Это параметры Java, а не общий объём
RAM компьютера. Для RegionalWorlds задано 8192/8192 МиБ; дополнительно нужен запас
памяти для Windows и других программ. Новые снимки создаются с этими значениями
по умолчанию, изменить границы можно аргументами `--min-memory-mib` и
`--max-memory-mib` у `scripts/tatarin/snapshot.py`.

При установке и синхронизации требования применяются к экземпляру; поля памяти
в настройках такого экземпляра недоступны для ручного изменения. Общие настройки
и обычные сборки не затрагиваются. Перед запуском проверяются общий и свободный
объёмы RAM. При нехватке памяти показывается предупреждение с требованием сборки,
общим и доступным объёмами. По умолчанию выбран отказ; автоматического снижения
памяти ниже требований нет. Отдельно предупреждается невозможность измерить RAM.
Если автор убирает объект `memory`, восстанавливаются прежние настройки экземпляра.
Старые манифесты без `memory` сохраняют прежнее поведение.

## Перенос клиентских данных

В настройках экземпляра откройте страницу «Данные клиента» и выберите игровую
папку другой сборки — ту, где находятся `config` и `options.txt`. Перенос доступен
для обычных экземпляров и TATARIN. Minecraft в обоих лаунчерах должен быть закрыт.
Текущий экземпляр нельзя запустить до завершения операции.

Копируются клиентские настройки, данные модов, карты и точки, список серверов,
ресурспаки, шейдеры, миры и скриншоты. Моды, скрипты, обязательные файлы манифеста,
кеши, логи, файлы аккаунтов и обнаруженные учётные данные исключаются. Перед
копированием показываются объём, количество и число пропусков. Исходник не
изменяется. Мир с совпадающим именем получает суффикс `_import_N`: содержимое
двух миров не смешивается. Открытый мир с занятым `session.lock` переносить нельзя.

Заменяемые файлы сохраняются в `client-data-import/backups/<transaction>/`
экземпляра. Сначала создаются временные копии, затем журнал `pending.json`,
после чего применяется перенос. До применения доступна отмена. Незавершённый
перенос восстанавливается перед следующим импортом или запуском. Если после
сбоя файл был изменён вручную, автоматическое восстановление останавливается,
чтобы не потерять новую правку. При ошибке подготовки временные копии могут
остаться в `client-data-import/work/`; автоматической очистки таких копий пока нет.

Конфиги, обязательные для сборки (`managed`), не импортируются. Клиентские
пресеты должны иметь политику `seed`, чтобы перенесённые настройки пережили
последующую синхронизацию. `snapshot.py` помечает как `seed` файлы `*-client.*`,
`*.client.*`, `*clientconfig.*` поддерживаемых форматов и папки из
`CLIENT_CONFIG_DIRS`. Для остальных файлов политику задаёт автор манифеста.
При публикации из существующего снимка можно применить те же правила через
`publish.py --client-presets` и задать границы памяти двумя аргументами
`--min-memory-mib 8192 --max-memory-mib 8192`. Ранее опубликованный выпуск
не изменяется: требуется новый ID выпуска модпака.

## Выполненные проверки

Для 0.3.0 отдельно проверены требования к RAM и перенос на искусственных данных:
защита обязательных конфигов, исключение учётных данных, совпадающие имена миров,
резервные копии, отмена, восстановление после сбоя, ручные правки после сбоя и
Windows junction. Проверено сохранение импортированных настроек после
синхронизации сборки. Проверка переноса собирается из `tests/client-data`.
Реальные пользовательские папки этими тестами не изменяются.

Проверены локальная Release-сборка и установка приложения, HTTP-установка снимка
RegionalWorlds (3604 файла), SHA-256 всех установленных файлов и повторная
синхронизация полного снимка. Автоматические проверки охватывают изменение состава,
восстановление повреждений, отмену, сбой применения, восстановление по журналу,
проверку локального выпуска при недоступном источнике, правила `seed`, резервные
копии конфигов, дополнительные моды, опасные пути и Windows junction.

Ручная работа новых экранов и запуск Minecraft с этой сборкой пока не проверены.
Инструмент автоматизации интерфейса не инициализировался (`failed to write kernel assets`).
Авторизация Ely.by и игровые сценарии требуют отдельной ручной проверки.
