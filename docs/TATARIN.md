# Локальная разработка TATARIN

Исходная игровая папка используется только для чтения. Снимки и раздача хранятся в
`run/`, исключённом из Git. Не добавляйте туда ссылки на исходные пользовательские папки.

## Снимок

Из корня репозитория, с Python 3.12 или новее:

```powershell
python scripts/tatarin/snapshot.py <исходная-папка> run/tatarin/snapshot-v1 --minecraft 1.21.1 --neoforge 21.1.264
```

Скрипт требует новый каталог назначения. Разрешённые корневые папки и политика
файлов перечислены в `scripts/tatarin/snapshot.py`. Миры, карты, история, кеши,
пользовательские файлы в корне и резервные копии не входят в снимок.
Конфиги с обнаруженными непустыми полями учётных данных исключаются без вывода значений.
Это дополнительный фильтр, а не гарантия обезличивания произвольных файлов:
перед публичной раздачей требуется ручная проверка состава и содержимого.

`snapshot.json` содержит только версии компонентов, относительные пути, размеры,
SHA-256 и политику файлов. `managed` означает управление сборкой, `seed` —
начальное содержимое с сохранением последующих пользовательских изменений.
Файлы вне разрешённых папок необходимо разбирать отдельно, не копировать автоматически.

## Локальный источник

```powershell
python scripts/tatarin/publish.py run/tatarin/snapshot-v1 run/tatarin/server --release local-1
python scripts/tatarin/serve.py run/tatarin/server
```

Источник доступен по `http://127.0.0.1:18765/`, завершение — Ctrl+C.
Сервер слушает только этот компьютер. Это инструмент разработки, не публичный хостинг.
Публикация копирует файлы в `objects/<sha256>`, затем создаёт неизменяемый манифест
и в последнюю очередь атомарно заменяет `v1/catalog.json`. ID выпуска повторно
использовать нельзя. Для следующего выпуска создайте новый снимок и новый ID.
Каталог содержит список сборок и SHA-256 их манифестов; манифест задаёт полный
состав выпуска, версии Minecraft/NeoForge и патчноут. Секреты и исходные абсолютные
пути в эти документы не записываются.

## Установка в лаунчере

В окне добавления сборки откройте `TATARIN`, нажмите «Обновить каталог» и выберите
RegionalWorlds. Адрес по умолчанию — `http://127.0.0.1:18765/`; он сохраняется
в настройке `TatarinDevSource`. Разрешён только HTTP на `127.0.0.1`, редиректы
отклоняются. Публичные источники до реализации подписей не поддерживаются.

Создаётся отдельный экземпляр типа `tatarin`. Minecraft и NeoForge устанавливаются
существующим механизмом лаунчера. Для загрузки их метаданных, библиотек и ресурсов
требуется интернет; локальная раздача содержит только содержимое модпака.
Установленный манифест хранится в `tatarin/installed.json` экземпляра.

Изолированный проверочный исполняемый файл собирается из `tests/tatarin/CMakeLists.txt`
с Qt6 Core/Network. Он принимает URL источника и новый каталог назначения,
проверяет установку через HTTP и SHA-256 всех установленных файлов.

## Проверка перед запуском

У экземпляров `tatarin` перед загрузкой метаданных Minecraft и подбором Java
выполняется синхронизация. Обычные экземпляры эту задачу не запускают.
Проверяются SHA-256 управляемых файлов, новые объекты сначала загружаются в
`tatarin/downloads/`. Неизменённые файлы повторно не скачиваются.

Перед заменой или удалением создаются копии в `tatarin/backups/<transaction>/`.
Журнал `tatarin/pending.json` сохраняется до первого изменения рабочих файлов.
При ошибке выполняется восстановление; после аварийного завершения оно повторяется
при следующей проверке. До успешного восстановления запуск останавливается.
На время применения отмена недоступна; параллельную синхронизацию блокирует lock-файл.
Резервные копии и кеш пока сохраняются без автоматической очистки.

Если источник недоступен, лаунчер предлагает запуск локального выпуска только
после проверки всех обязательных файлов. По умолчанию выбран отказ. Ошибка
формата, опасные пути или несовпадение хешей не обходятся этим предложением.

Интеграционные проверки: `python tests/tatarin/integration.py <путь-к-tatarin-check.exe>`.
Для запуска нужны Qt DLL в `PATH`; проверки используют временные папки и собственный
loopback-сервер, не затрагивают исходную сборку и пользовательские экземпляры.

## Владение файлами

Политика задаётся для каждого файла манифеста:

| Политика | Поведение |
| --- | --- |
| `managed` | Восстановление содержимого по SHA-256; замена и удаление с резервной копией |
| `seed` | Добавление нового стартового файла, если его ещё нет; сохранение пользовательских изменений и удаления |

Реестр `initializedSeeds` в локальном манифесте сохраняет факт выдачи стартовых
файлов даже после их исчезновения из следующих выпусков. Удалять пользовательский
файл или возвращать ранее удалённый `seed` синхронизация не будет.
Устаревшие файлы удаляются только по предыдущему манифесту и только с политикой `managed`.
Папки целиком не очищаются. Локальные изменения обязательных конфигов уступают
манифесту, их исходное содержимое остаётся в резервных копиях экземпляра.

Дополнительные моды, включая `.disabled`, сохраняются. Предупреждение об их наличии
выводится в журнал запуска, список виден на странице `TATARIN` настроек экземпляра.
Там же показаны установленный выпуск, версии компонентов, патчноут и правила файлов.
Ссылки и Windows junction в управляемых путях не поддерживаются.

## Выполненные проверки

Проверены локальная Release-сборка и установка приложения, HTTP-установка снимка
RegionalWorlds (3604 файла), SHA-256 всех установленных файлов и повторная
синхронизация полного снимка. Автоматические проверки охватывают изменение состава,
восстановление повреждений, отмену, сбой применения, восстановление по журналу,
проверку локального выпуска при недоступном источнике, правила `seed`, резервные
копии конфигов, дополнительные моды, опасные пути и Windows junction.

Ручная работа новых экранов и запуск Minecraft с этой сборкой пока не проверены.
Инструмент автоматизации интерфейса не инициализировался (`failed to write kernel assets`).
Авторизация Ely.by и игровые сценарии требуют отдельной ручной проверки.
