# OldMoneyTatarin

OldMoneyTatarin — Minecraft-лаунчер на основе PineconeMC, форка Prism Launcher.

- Документация на русском языке; сохраняй исходные имена API, файлов и команд.
- До отдельного задания не реализуй MCP Sync, новые функции, ребрендинг интерфейса, установщик или обновление лаунчера.
- Сохраняй существующие механизмы Ely.by, скинов, установки Minecraft, загрузчиков и сборок. В `develop` разрешено упрощать структуру под Windows; сохранять все файлы upstream не требуется.
- Не заменяй собственные документы и настройки вслепую при обновлении upstream. Порядок синхронизации описан в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
- Не изменяй системные настройки и не устанавливай глобальные зависимости без необходимости; предпочитай изолированное окружение сборки.
- Собирай и упаковывай приложение локально. Не добавляй GitHub Actions для сборки или публикации; не загружай бинарники, установщики и результаты сборки в Git, GitHub Releases или Actions artifacts. В репозитории хранятся код и документация.
- Сохраняй сведения об авторах, лицензии и уведомления upstream и зависимостей. Не объявляй лицензию форка до проверки исходников.
- Не сохраняй в Git и отчётах токены Ely.by, пароли, cookies, ключи подписи и пользовательские данные.
- Не выдавай предполагаемые пути и компоненты за проверенные; отмечай непроверенные сведения и пропущенные проверки.
- Коммиты, push, PR и merge выполняй только по отдельному поручению пользователя.
- Запускай дополнительных агентов только по разрешению пользователя.

## Ветки

- `vendor/pineconemc` содержит чистый стабильный upstream с его историей; не добавляй туда наши изменения. Источник — remote `upstream`, обновление только после выбора стабильного релиза.
- `develop` — рабочая и планируемая ветка по умолчанию нашего репозитория; направляй рабочие PR в неё.
- `main` предназначена только для подготовки и хранения выпусков; переноси туда проверенные изменения из `develop`.
- Сохраняй родительскую связь при интеграции `vendor/pineconemc` в `develop`: не используй squash для этих слияний.
- Версию продукта изменяй в `VERSION`; теги выпуска имеют вид `vX.Y.Z`. В `CHANGELOG.md` записывай только патчноуты лаунчера. Порядок выпуска описан в [docs/RELEASING.md](docs/RELEASING.md).
